# MAXbot - Бот для обучения цифровой безопасности

## 🚀 Быстрый старт с Docker

```bash
# 1. Создайте файл .env с токеном бота
echo "MAX_BOT_TOKEN=your_bot_token_here" > .env

# 2. Запустите через Docker Compose
docker-compose up -d

# 3. Проверьте логи
docker-compose logs -f
```

Подробные инструкции см. в разделе [🐳 Запуск через Docker](#-запуск-через-docker)

## 📋 Описание

MAXbot — это образовательный Telegram-бот, разработанный на платформе MAX Bot API, который помогает пользователям изучать основы цифровой гигиены и безопасности в интернете. Бот предоставляет интерактивное обучение через модули с теорией и практическими заданиями (квизами).

## 🗄️ База данных

### Схема базы данных

База данных использует SQLite с режимом WAL (Write-Ahead Logging) для повышения производительности при параллельных операциях.

#### Таблица `users`

Хранит информацию о пользователях и их прогрессе обучения.

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | TEXT (PRIMARY KEY) | Уникальный идентификатор пользователя |
| `first_name` | TEXT | Имя пользователя |
| `last_name` | TEXT | Фамилия пользователя |
| `username` | TEXT | Username пользователя |
| `state` | TEXT (NOT NULL) | Текущее состояние пользователя в боте |
| `current_module_id` | TEXT | ID модуля, который пользователь сейчас изучает |
| `completed_modules` | TEXT (NOT NULL) | JSON-массив ID завершённых модулей |
| `quiz_progress` | TEXT | JSON-объект с прогрессом прохождения квиза |
| `last_message_id` | TEXT | ID последнего сообщения для редактирования |
| `created_at` | TEXT (NOT NULL) | Дата и время создания записи (ISO формат) |
| `updated_at` | TEXT (NOT NULL) | Дата и время последнего обновления (ISO формат) |

### Операции с базой данных

#### Подготовленные запросы (Prepared Statements)

1. **`getUserStmt`** - Получение данных пользователя
   ```sql
   SELECT user_id, first_name, last_name, username, state, 
          current_module_id, completed_modules, quiz_progress, 
          last_message_id, created_at, updated_at 
   FROM users 
   WHERE user_id = ?
   ```

2. **`insertUserStmt`** - Создание нового пользователя
   ```sql
   INSERT INTO users (user_id, first_name, last_name, username, 
                      state, current_module_id, completed_modules, 
                      quiz_progress, last_message_id, created_at, updated_at)
   VALUES (@user_id, @first_name, @last_name, @username, @state, 
           @current_module_id, @completed_modules, @quiz_progress, 
           @last_message_id, @created_at, @updated_at)
   ```

3. **`updateUserStmt`** - Обновление данных пользователя
   ```sql
   UPDATE users
   SET first_name = @first_name,
       last_name = @last_name,
       username = @username,
       state = @state,
       current_module_id = @current_module_id,
       completed_modules = @completed_modules,
       quiz_progress = @quiz_progress,
       last_message_id = @last_message_id,
       updated_at = @updated_at
   WHERE user_id = @user_id
   ```

### JSON-структуры в базе данных

#### `completed_modules`
Массив строк с ID завершённых модулей:
```json
["module1", "module2"]
```

#### `quiz_progress`
Объект с прогрессом прохождения квиза:
```json
{
  "moduleId": "module1",
  "questionIndex": 3,
  "correctCount": 2,
  "answers": [
    {"questionIndex": 0, "answerIndex": 1, "isCorrect": true},
    {"questionIndex": 1, "answerIndex": 0, "isCorrect": false}
  ],
  "wrongAnswers": [
    {"questionIndex": 1, "selectedIndex": 0}
  ]
}
```

## 🔄 Состояния пользователя (User States)

Бот использует систему состояний для отслеживания текущей активности пользователя:

| Состояние | Описание |
|-----------|----------|
| `awaiting_module_selection` | Пользователь выбирает модуль для изучения |
| `viewing_theory` | Пользователь изучает теоретический материал модуля |
| `in_quiz` | Пользователь проходит практическое задание (квиз) |
| `awaiting_module_retry` | Пользователь не набрал проходной балл и должен повторить модуль |
| `awaiting_password_check` | Пользователь ожидает проверки пароля (не реализовано полностью) |

## 🎯 Основные объекты и функции

### 1. Инициализация бота

```javascript
const bot = new Bot(BOT_TOKEN);
```

Бот инициализируется с токеном из переменной окружения `MAX_BOT_TOKEN` или использует токен по умолчанию.

### 2. Управление пользователями

#### `ensureUser(ctx)`
**Назначение**: Обеспечивает существование пользователя в базе данных и возвращает его данные.

**Логика работы**:
1. Извлекает `user_id` из контекста через `getUserId(ctx)`
2. Извлекает профиль пользователя через `extractUserProfile(ctx)`
3. Проверяет существование пользователя в БД
4. Если пользователь не найден:
   - Создаёт новую запись с начальным состоянием `awaiting_module_selection`
   - Инициализирует пустые массивы и null значения
5. Если пользователь найден:
   - Парсит JSON-поля (`completed_modules`, `quiz_progress`)
   - Обновляет профиль (имя, фамилия, username) при изменениях
6. Возвращает объект `userData`

**Структура `userData`**:
```javascript
{
  userId: string,
  firstName: string,
  lastName: string,
  username: string,
  state: string,
  currentModuleId: string | null,
  completedModules: string[],
  quizProgress: object | null,
  lastMessageId: string | null
}
```

#### `saveUser(userData)`
**Назначение**: Сохраняет или обновляет данные пользователя в базе данных.

**Логика работы**:
1. Сериализует массивы и объекты в JSON (`completed_modules`, `quiz_progress`)
2. Устанавливает `updated_at` в текущее время (ISO формат)
3. Выполняет `updateUserStmt` с параметрами пользователя

#### `getUserId(ctx)`
**Назначение**: Извлекает идентификатор пользователя из контекста бота.

**Логика работы**:
1. Проверяет множество возможных путей в объекте контекста:
   - `ctx.from.id` / `ctx.from.user_id`
   - `ctx.chat.id` / `ctx.chat.chat_id` / `ctx.chat.user_id`
   - `ctx.sender.id` / `ctx.sender.user_id`
   - `ctx.message.sender.id` / `ctx.message.chat.id` / `ctx.message.recipient.*`
   - `ctx.update.sender.*` / `ctx.update.recipient.*` / `ctx.update.message.*`
2. Возвращает первый найденный валидный ID как строку
3. Выбрасывает ошибку, если ID не найден

#### `extractUserProfile(ctx)`
**Назначение**: Извлекает профильную информацию пользователя (имя, фамилия, username).

**Логика работы**:
1. Проверяет различные источники в контексте:
   - `ctx.update.message.sender`
   - `ctx.update.callback.user`
   - `ctx.from`
   - `ctx.sender`
2. Извлекает `first_name`/`name`/`firstName`, `last_name`/`lastName`, `username`
3. Возвращает объект `{ firstName, lastName, username }`

### 3. Управление модулями

#### `getModuleById(moduleId)`
**Назначение**: Находит модуль по его ID.

**Логика**: Линейный поиск в массиве `modules` по полю `id`.

#### `getLockedModule(userData)`
**Назначение**: Определяет, есть ли у пользователя незавершённый модуль.

**Логика работы**:
1. Проверяет состояние `awaiting_module_retry`
2. Если состояние соответствует и есть `currentModuleId`, возвращает модуль
3. Иначе возвращает `null`

#### `resetUserState(userData)`
**Назначение**: Сбрасывает состояние пользователя к начальному.

**Логика**:
- Устанавливает `state = 'awaiting_module_selection'`
- Очищает `currentModuleId` и `quizProgress`
- Сохраняет изменения в БД

#### `resetProgress(userData)`
**Назначение**: Полностью сбрасывает прогресс обучения.

**Логика**:
- Очищает массив `completedModules`
- Вызывает `resetUserState(userData)`

### 4. Работа с теорией

#### `startModuleTheory(ctx, module, userData)`
**Назначение**: Начинает изучение теоретического материала модуля.

**Логика работы**:
1. Устанавливает `currentModuleId = module.id`
2. Устанавливает `state = 'viewing_theory'`
3. Очищает `quizProgress` и `lastMessageId`
4. Сохраняет изменения в БД
5. Отправляет отформатированную теорию через `formatTheory(module)`
6. Отправляет клавиатуру с кнопкой "🧩 Начать практику"

#### `formatTheory(module)`
**Назначение**: Форматирует теоретический материал модуля.

**Логика**: Объединяет массив строк `module.theory` через `\n`.

### 5. Работа с квизами

#### `startModuleQuiz(ctx, module, userData)`
**Назначение**: Начинает прохождение практического задания (квиза).

**Логика работы**:
1. Устанавливает `state = 'in_quiz'`
2. Устанавливает `currentModuleId = module.id`
3. Инициализирует объект `quizProgress`:
   ```javascript
   {
     moduleId: module.id,
     questionIndex: 0,
     correctCount: 0,
     answers: [],
     wrongAnswers: []
   }
   ```
4. Очищает `lastMessageId`
5. Сохраняет изменения в БД
6. Вызывает `sendQuizQuestion()` для отправки первого вопроса

#### `sendQuizQuestion(ctx, module, userData)`
**Назначение**: Отправляет текущий вопрос квиза пользователю.

**Логика работы**:
1. Проверяет наличие `quizProgress`
2. Если `questionIndex >= total`, вызывает `finalizeQuiz()`
3. Форматирует вопрос через `formatQuizQuestion()`
4. Создаёт клавиатуру с вариантами ответов через `buildQuizKeyboard()`
5. Отправляет или редактирует сообщение через `sendOrEditMessage()`

#### `formatQuizQuestion(module, questionIndex)`
**Назначение**: Форматирует текст вопроса для отправки.

**Логика работы**:
1. Получает вопрос из `module.quiz.questions[questionIndex]`
2. Форматирует заголовок с номером вопроса и общим количеством
3. На первом вопросе добавляет информацию о проходном балле
4. Форматирует варианты ответов с номерами
5. Возвращает полный текст вопроса

#### Обработка ответа на вопрос (`bot.action(/quiz_answer:.+/)`)
**Назначение**: Обрабатывает выбор варианта ответа пользователем.

**Логика работы**:
1. Извлекает `moduleId`, `questionIndex`, `answerIndex` из payload
2. Проверяет валидность модуля и состояния пользователя
3. Проверяет, что вопрос ещё не пройден (`questionIndex === progress.questionIndex`)
4. Определяет правильность ответа (`answerIndex === question.correctIndex`)
5. Обновляет `quizProgress`:
   - Если правильно: увеличивает `correctCount`
   - Если неправильно: добавляет в `wrongAnswers`
   - Добавляет запись в `answers`
6. Формирует обратную связь (feedback):
   - ✅ Верно: "Верно! Отличная работа 💪"
   - ❌ Неверно: "Неверно. Правильный ответ — [ответ]. 💡 [объяснение]"
7. Обновляет сообщение с вопросом, добавляя feedback
8. Увеличивает `questionIndex` на 1
9. Сохраняет изменения в БД
10. Показывает кнопку "➡️ Дальше" или "📊 Посмотреть итоги"

#### `finalizeQuiz(ctx, module, userData)`
**Назначение**: Завершает квиз и подводит итоги.

**Логика работы**:
1. Извлекает данные из `quizProgress`
2. Вычисляет результат: `score = correctCount`, `total = questions.length`
3. Определяет, пройден ли модуль: `passed = score >= module.quiz.passingScore`
4. Формирует итоговое сообщение:
   - Количество правильных ответов
   - Проходной балл
   - Статус (пройден/не пройден)
   - Список ошибок с объяснениями (если есть)
5. Если модуль пройден:
   - Добавляет `module.id` в `completedModules` (если ещё нет)
   - Устанавливает `state = 'awaiting_module_selection'`
   - Очищает `currentModuleId` и `quizProgress`
   - Сохраняет изменения
   - Показывает клавиатуру с опциями (другие модули, прогресс, повторить)
   - Отправляет обновлённый прогресс
6. Если модуль не пройден:
   - Устанавливает `state = 'awaiting_module_retry'`
   - Сохраняет `currentModuleId = module.id`
   - Очищает `quizProgress`
   - Сохраняет изменения
   - Показывает клавиатуру для повтора (практика заново, теория, прогресс)

### 6. Клавиатуры (Keyboards)

Бот использует inline-клавиатуры для интерактивного взаимодействия. Все клавиатуры создаются через объект `Keyboard` из `@maxhub/max-bot-api`.

#### Префиксы callback-данных

```javascript
MODULE_SELECT_PREFIX = 'module_select:'
QUIZ_ANSWER_PREFIX = 'quiz_answer:'
START_PRACTICE_PREFIX = 'start_practice:'
RETRY_MODULE_PREFIX = 'retry_module:'
NEXT_QUESTION_PREFIX = 'next_question:'
```

#### `buildMainMenuKeyboard(userData)`
**Назначение**: Создаёт главное меню с учётом текущего состояния пользователя.

**Структура**:
- Если `state === 'in_quiz'`: кнопка "🧩 Продолжить"
- Если `state === 'awaiting_module_retry'`: кнопка "🧩 Завершить"
- Основные кнопки:
  - "🚀 Начать обучение" → `modules_menu`
  - "📊 Прогресс" → `show_progress`
  - "📚 Статьи" → `articles_menu`
  - "🔐 Создать пароль" → `generate_password_action`
  - "🔁 Сбросить прогресс" → `restart_learning`

#### `buildModulesKeyboard(userData)`
**Назначение**: Создаёт клавиатуру выбора модулей.

**Логика**:
- Для каждого модуля создаётся кнопка с иконкой и названием
- Добавляются суффиксы: ✅ (завершён), 🔒 (заблокирован)
- Каждый модуль в отдельной строке
- Внизу: "📊 Мой прогресс", "🔁 Сбросить"

#### `buildTheoryKeyboard(module)`
**Назначение**: Клавиатура после изучения теории.

**Структура**:
- "🧩 Начать практику" → `start_practice:{moduleId}`
- "📚 Список модулей" → `modules_menu`
- "📊 Прогресс" → `show_progress`

#### `buildQuizKeyboard(module, questionIndex)`
**Назначение**: Клавиатура с вариантами ответов на вопрос.

**Логика**:
- Создаёт кнопки с эмодзи-номерами (1️⃣, 2️⃣, 3️⃣, ...)
- Callback: `quiz_answer:{moduleId}:{questionIndex}:{answerIndex}`
- Все кнопки в одну строку

#### `buildNextQuestionKeyboard(module, nextQuestionIndex)`
**Назначение**: Клавиатура после ответа на вопрос.

**Логика**:
- Если вопросы закончились: "📊 Посмотреть итоги"
- Иначе: "➡️ Дальше"
- Callback: `next_question:{moduleId}`

#### `buildPostQuizKeyboard(userData, module)`
**Назначение**: Клавиатура после успешного завершения квиза.

**Структура**:
- "📚 Другие модули" → `modules_menu`
- "📊 Прогресс" → `show_progress`
- "🔁 Ещё раз" → `module_select:{moduleId}`

#### `buildRetryKeyboard(module)`
**Назначение**: Клавиатура при необходимости повтора модуля.

**Структура**:
- "🔄 Практика заново" → `start_practice:{moduleId}`
- "📘 Теория" → `retry_module:{moduleId}`
- "📊 Прогресс" → `show_progress`

#### `buildArticlesKeyboard()`
**Назначение**: Клавиатура со списком статей.

**Логика**:
- Каждая статья — кнопка-ссылка (Keyboard.button.link)
- Внизу: "🏠 Главное меню"

#### `buildPasswordToolsKeyboard()`
**Назначение**: Клавиатура для инструментов работы с паролями.

**Структура**:
- "🔐 Создать ещё" → `generate_password_action`
- "🏠 Главное меню" → `modules_menu`

### 7. Отправка сообщений

#### `sendOrEditMessage(ctx, userData, text, options)`
**Назначение**: Отправляет новое сообщение или редактирует существующее.

**Логика работы**:
1. Если есть `userData.lastMessageId`:
   - Пытается отредактировать сообщение через `ctx.editMessage()` или `ctx.api.editMessage()`
   - При ошибке продолжает к отправке нового
2. Если редактирование невозможно или `lastMessageId` отсутствует:
   - Отправляет новое сообщение через `ctx.reply()`
   - Сохраняет `mid` или `messageId` в `userData.lastMessageId`
   - Сохраняет изменения в БД

### 8. Отображение информации

#### `sendWelcome(ctx, userData)`
**Назначение**: Отправляет приветственное сообщение.

**Логика**:
- Формирует персонализированное приветствие с именем пользователя
- Если есть незавершённый модуль, добавляет предупреждение
- Показывает главное меню

#### `sendModuleMenu(ctx, userData, message)`
**Назначение**: Отображает список модулей для выбора.

**Логика**:
1. Форматирует список модулей с иконками, названиями и статусами
2. Добавляет информацию о заблокированном модуле (если есть)
3. Отправляет сообщение с клавиатурой выбора модулей

#### `sendProgress(ctx, userData, options)`
**Назначение**: Отображает прогресс обучения пользователя.

**Логика работы**:
1. Вычисляет процент прогресса через `calculateProgress(userData)`
2. Формирует список завершённых модулей с иконками
3. Добавляет информацию о заблокированном модуле (если есть)
4. Отправляет сообщение с прогрессом и опциональной клавиатурой

#### `calculateProgress(userData)`
**Назначение**: Вычисляет процент завершённых модулей.

**Формула**: `(completedModules.length / modules.length) * 100`

#### `sendArticlesMenu(ctx, userData)`
**Назначение**: Отображает меню со статьями по безопасности.

**Логика**:
- Форматирует список статей
- Отправляет сообщение с клавиатурой-ссылками на статьи

### 9. Генерация паролей

#### `generateSecurePassword(length = 16)`
**Назначение**: Генерирует безопасный пароль заданной длины.

**Логика работы**:
1. Определяет наборы символов:
   - `uppercase`: A-Z
   - `lowercase`: a-z
   - `numbers`: 0-9
   - `special`: !@#$%^&*()_+-=[]{}|;:,.<>?
2. Гарантирует наличие всех типов символов:
   - Добавляет по одному символу из каждого набора
3. Заполняет остальные позиции случайными символами из всех наборов
4. Перемешивает символы для случайного порядка
5. Возвращает готовый пароль

### 10. Обработчики команд

#### `/start`
**Назначение**: Главная команда для начала работы с ботом.

**Логика**:
1. Получает данные пользователя через `ensureUser()`
2. Если пользователь в процессе квиза, возвращает к текущему вопросу
3. Если есть незавершённый модуль, предлагает его завершить
4. Сбрасывает состояние и отправляет приветствие

#### `/help`
**Назначение**: Показывает список доступных команд.

**Логика**: Отправляет описание всех команд и показывает главное меню.

#### `/modules`
**Назначение**: Открывает меню выбора модулей.

**Логика**:
1. Проверяет, не проходит ли пользователь квиз
2. Проверяет наличие незавершённого модуля
3. Отправляет меню модулей

#### `/progress`
**Назначение**: Показывает текущий прогресс обучения.

**Логика**: Вызывает `sendProgress()` с данными пользователя.

#### `/restart`
**Назначение**: Сбрасывает весь прогресс обучения.

**Логика**:
1. Вызывает `resetProgress(userData)`
2. Отправляет подтверждение и главное меню

#### `/articles`
**Назначение**: Открывает меню со статьями по безопасности.

**Логика**: Вызывает `sendArticlesMenu()`.

#### `/generate_password`
**Назначение**: Генерирует безопасный пароль.

**Логика**:
1. Генерирует пароль длиной 16 символов
2. Отправляет пароль с описанием характеристик
3. Показывает клавиатуру для дополнительных действий

#### `module_select:{moduleId}`
**Назначение**: Обработка выбора модуля из списка.

**Логика**:
1. Проверяет валидность модуля
2. Проверяет, не проходит ли пользователь другой квиз

#### `start_practice:{moduleId}`
**Назначение**: Начало практического задания (квиза).

**Логика**:
1. Проверяет валидность модуля
2. Если пользователь уже проходит этот квиз, возвращает к текущему вопросу
3. Проверяет блокировку других модулей
4. Запускает квиз

#### `retry_module:{moduleId}`
**Назначение**: Повторное изучение теории модуля.

**Логика**: Запускает `startModuleTheory()` для указанного модуля.

#### `quiz_answer:{moduleId}:{questionIndex}:{answerIndex}`
**Назначение**: Обработка ответа на вопрос квиза.

**Логика**: (см. раздел "Обработка ответа на вопрос")

#### `next_question:{moduleId}`
**Назначение**: Переход к следующему вопросу квиза.

**Логика**:
1. Проверяет валидность модуля и состояния
2. Если вопросы закончились, завершает квиз
3. Иначе отправляет следующий вопрос

#### `modules_menu`
**Назначение**: Возврат к меню модулей.

**Логика**: Аналогична команде `/modules`.

#### `show_progress`

#### `articles_menu`

#### `restart_learning`

**Логика**: Аналогична команде `/restart`.

#### `generate_password_action`
**Назначение**: Генерация пароля через кнопку.

**Логика**: Аналогична команде `/generate_password`.

#### `check_password_action`
**Назначение**: Проверка надёжности пароля (частично реализовано).

**Логика**: Устанавливает состояние `awaiting_password_check` (полная реализация отсутствует).

### 12. Обработчики текстовых сообщений

#### `bot.hears('🚀 Начать обучение')`
**Назначение**: Обработка нажатия кнопки "Начать обучение".

**Логика**: Аналогична команде `/modules`.

#### `bot.hears('📊 Прогресс')`
**Назначение**: Обработка нажатия кнопки "Прогресс".

**Логика**: Вызывает `sendProgress()`.

#### `bot.hears('🔁 Сбросить прогресс')`
**Назначение**: Обработка нажатия кнопки "Сбросить прогресс".

**Логика**: Вызывает `resetProgress()`.

#### `bot.on('message')`
**Назначение**: Обработка всех текстовых сообщений.

**Логика работы**:
1. Извлекает текст сообщения из различных возможных мест в контексте
2. Пропускает команды (начинающиеся с `/`)
3. Если пользователь в процессе квиза, напоминает использовать кнопки
4. Если пользователь изучает теорию, напоминает начать практику
5. Если есть незавершённый модуль, напоминает о необходимости его завершить
6. Иначе предлагает использовать команды или кнопки

### 13. Вспомогательные функции

#### `getCallbackPayload(ctx)`
**Назначение**: Извлекает payload из callback-запроса.

**Логика**:
- Проверяет `ctx.update.callback.payload` / `data`
- Проверяет `ctx.callback.payload` / `data`
- Проверяет `ctx.callbackQuery.data`
- Возвращает строку или пустую строку

#### `parseJson(value, fallback)`
**Назначение**: Безопасный парсинг JSON с fallback значением.

**Логика**:
1. Проверяет, что значение — строка
2. Пытается распарсить через `JSON.parse()`
3. При ошибке возвращает `fallback`

#### `ensureDatabase()`
**Назначение**: Создаёт директорию для базы данных, если её нет.

**Логика**: Проверяет существование `db/` и создаёт при необходимости.

## 🔐 Безопасность

### Токен бота

Токен бота хранится в переменной окружения `MAX_BOT_TOKEN` или используется значение по умолчанию (для разработки). В продакшене рекомендуется использовать только переменные окружения.

### База данных

- Используется SQLite с режимом WAL для повышения производительности
- Подготовленные запросы (prepared statements) защищают от SQL-инъекций
- Все JSON-данные валидируются при парсинге

### Обработка ошибок

- Функции парсинга JSON имеют fallback-значения
- Обработка ошибок редактирования сообщений с graceful degradation
- Проверка валидности данных перед использованием

Минимальные характеристики устройства для стабильной работы бота (с запасом):

## 🐳 Запуск через Docker

Проект поддерживает запуск через Docker, что упрощает развёртывание и обеспечивает изолированную среду выполнения.

### Требования для Docker

- Docker версии 20.10 или выше
- Docker Compose версии 1.29 или выше (опционально, для docker-compose)

### Способ 1: Использование Docker Compose (рекомендуется)

**Перед запуском контейнера убедитесь, что установлен NPM.**

   ```bash
   npm install
   ```

1. **Отредактируйте файл `.env` в корне проекта:**
   ```bash
   MAX_BOT_TOKEN=token
   ```

2. **Запустите контейнер:**
   ```bash
   docker-compose up -d
   ```

3. **Проверьте логи:**
   ```bash
   docker-compose logs -f
   ```

4. **Остановите контейнер:**
   ```bash
   docker-compose down
   ```

### Способ 2: Использование Docker напрямую

1. **Соберите образ:**
   ```bash
   docker build -t maxbot .
   ```

2. **Запустите контейнер:**
   ```bash
   docker run -d \
     --name maxbot \
     --restart unless-stopped \
     -e MAX_BOT_TOKEN=token \
     -v $(pwd)/db:/app/db \
     maxbot
   ```

3. **Проверьте логи:**
   ```bash
   docker logs -f maxbot
   ```

4. **Остановите контейнер:**
   ```bash
   docker stop maxbot
   ```

### Важные замечания

- **База данных**: Директория `db/` монтируется как volume, чтобы данные сохранялись при перезапуске контейнера
- **Переменные окружения**: Токен бота передаётся через переменную окружения `MAX_BOT_TOKEN`
- **Автозапуск**: Контейнер настроен на автоматический перезапуск при сбое (`restart: unless-stopped`)
- **Логи**: Используйте `docker logs` для просмотра логов работы бота

### Проверка работы

После запуска контейнера проверьте, что бот работает:

```bash
# Проверка статуса контейнера
docker ps | grep maxbot

# Просмотр логов
docker logs maxbot
```

В логах не должно быть ошибок, и бот должен успешно подключиться к платформе MAX.

## 🔄 Жизненный цикл пользователя

1. **Регистрация**: При первом обращении создаётся запись в БД с начальным состоянием
2. **Выбор модуля**: Пользователь выбирает модуль из списка
3. **Изучение теории**: Пользователь читает теоретический материал
4. **Практика**: Пользователь проходит квиз с вопросами
5. **Результат**: 
   - Если набрано ≥8 правильных ответов → модуль завершён, доступны другие модули
   - Если <8 правильных ответов → необходимо повторить модуль
6. **Повтор**: Пользователь может перечитать теорию или сразу начать практику заново

## 🎓 Система оценивания

- Каждый модуль содержит 10 вопросов
- Проходной балл: 8 из 10 правильных ответов (80%)
- После завершения квиза показываются:
  - Общее количество правильных ответов
  - Список ошибок с правильными ответами и объяснениями
  - Статус прохождения модуля
